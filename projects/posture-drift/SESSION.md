# Session submission worksheet

Use the three sections in REVIEW.md for the task description, how to judge completion and other reviewer notes. Keep this worksheet outside the source upload if the platform requests a clean repository.

| Form field | Entry |
| --- | --- |
| Live compare problem ID | Copy the new run ID from the platform. |
| Total hours worked | Enter measured active minutes divided by 60. |
| Primary programming language | Python |
| What kind of task was it? | Feature implementation with regression testing and reporting. Select the matching platform option. |
| Where did the code come from? | Existing SignalDesk repository, yeabsira-mesfin/endpoint-posture-advisor, MIT licensed. This starter and its acceptance fixtures were prepared with Codex. |
| How did the task end? | Record the actual outcome and outstanding failures. |
| If completed, how did you check? | Paste the real command, exit status, test totals and one observed CLI comparison. |
| What should the reviewer check? | List actual changed paths and tests. Use REVIEW.md to select the relevant checks. |
| About how many turns? | Count the actual session turns. |
| How many responses were flagged? | Count actual flags. |
| Which categories? | Select observed categories only: writing, intent disambiguation, knowledge-state calibration, effort calibration, unstated constraints, proactivity calibration, honesty, overconfidence, agentic safety, other, or none. |
| Evidence for a flag or model preference | Quote the exact response, identify turn/model and explain the observed consequence. |
