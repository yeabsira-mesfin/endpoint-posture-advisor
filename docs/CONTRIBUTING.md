# Contributing

Keep contributions focused, testable, and safe for a synthetic security lab.

1. Create a branch for one scoped change.
2. Add or update tests when behavior changes.
3. Keep examples synthetic and never commit credentials or customer data.
4. Document security assumptions when adding networking, persistence, AI integrations, or write operations.
5. Open a pull request with verification steps and risk notes.

Security-sensitive changes should explicitly test authorization, tenant/customer isolation, unsafe input handling, and failure behavior where relevant.
